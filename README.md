# ワイン テイスティング練習（wine-tasting-trainer）

ワインエキスパート2次試験（テイスティング）対策の個人用PWAです。
iPhone / iPad のSafariで開き「共有 → ホーム画面に追加」するとアプリとして使えます。
幅768px以上（iPad）では、ランチャーが3列、用語シート・採点結果・出題傾向などが2列になります（`style.css` 末尾のメディアクエリ）。

## 機能

- 📝 **テイスティングコメント選択練習** — 本番の解答用紙を模した用語選択シートで回答し、模範解答と照合・採点。用語シートは「ワイン受験.com 2026年版」と「Wine-Flight 2025年版（番号付き）」を切り替え可能。採点結果は白・赤それぞれ最新5回分を端末内に記録し、タップで再表示、削除はユーザー操作のみ
- 🃏 **主要品種フラッシュカード** — 白11種・赤15種の計26品種の特徴（外観・香り・味わい・決め手・主産地）を暗記。🥃 その他の酒類32種（ブランデー・ウイスキー・スピリッツ・リキュールなど）も分類・原料・産地・外観・香り・味わい・度数・決め手で暗記できる
- ❓ **品種当てクイズ** — 模範解答から生成したコメントを読んで品種を4択で推測。🥃 その他の酒類モードでは外観・香り・味わい・度数から酒類名を当てる
- 🧭 **タイプ別テッパンコメント** — 淡い白／濃い白／淡い赤／濃い赤／特殊の5タイプ別に、項目ごとの定石と条件分岐を一覧
- 📊 **過去の出題品種 傾向データ** — 2011〜2025年の出題実績ランキング（品種別・生産国別、🥃 その他の酒類）と年度別一覧（ヴィンテージ・出題番号・ソムリエ試験分を含む）。模範解答がある出題は品種名から過去問アーカイブへ直接移動できる
- 🗄️ **過去問アーカイブ** — 本試験で実際に発表された模範解答（2015〜2025年の52本）。模範解答がある回は「この正解で採点する練習へ」から用語シートに移れる
- 🔎 **国・品種からコメントを探す** — 生産国と品種（片方だけでも可）で絞り込み、実物過去問・AI参考解答・テイスティング会メモの全コメントを横断して一覧。1本ずつ開いて全項目の正解を見るか、比較表（横並び・全本共通の語を強調）で見比べられ、そのまま採点練習や過去問アーカイブへ移れる
- 🔍 **実物正解 品種×年度 横断** — 同じ品種の実物正解を年度横並びで見比べ、全回で共通する語を強調
- 📈 **用語の採用率** — 52本の実物正解から項目ごとに各用語の採用回数を集計（白／赤、全年度／現行様式／旧様式）
- 🍷 **テイスティング会メモ** — 2026年9月12日（土）16:30〜18:00＠まるすけ（阿佐ヶ谷）のテイスティング会で取った手書きメモ6本を模範解答の形で閲覧（Wine-Flight 2025年版なら番号付き）。白3本・赤3本を横並びにして共通する語を太字にする比較表も切り替えられる。そのまま採点練習にも進める。コメント練習の一覧・クイズ・推定には含めない
- 🎓 **本番セット練習** — 年度と試験区分を選び、その回の出題（WE 4本／ソムリエ 3本）を番号順にブラインドで通して採点

## データの編集

| ファイル | 定数 | 内容 |
|---|---|---|
| `data.js` | `VOCAB` | 用語選択シートの項目・用語・選択数（白/赤別、ワイン受験.com 2026年版） |
| `sheets.js` | `SHEETS` / `VOCAB_WF2025` | 切り替え可能な用語シートの定義。Wine-Flight 2025年版と、模範解答をシートの用語へ読み替える `sheetAnswers()` |
| `data.js` | `WINES` | 練習用ワインと模範解答（コメント練習・クイズ共通） |
| `data.js` | `GRAPES` | フラッシュカードの品種データ |
| `data.js` | `NOTE_SESSION` | テイスティング会の開催情報（日時・会場・使用シート） |
| `data.js` | `OTHERS` | その他の酒類（フラッシュカード・クイズ共通。本試験で出た19種＋定番） |
| `data.js` | `PAST_EXAMS` | 過去の出題実績 |
| `past-answers.js` | `PAST_ANSWERS` | 本試験の実物の模範解答 |
| `teppan.js` | `TEPPAN` | タイプ別テッパンコメント |

用語・選択数はJ.S.A.解答用紙の近似です。最新の本番シートに合わせて編集してください。
グラスは2025年の試験から「小ぶり／中庸／大ぶり」から1つと「バルーン型／チューリップ型」から1つの2語を選ぶ指定になったため、
`pick: 2` に加えて `subsets`（各グループから1語ずつ）を定義しています。同じ仕組みで他の項目にもグループ制約を付けられます。
実物の模範解答で採点する練習（`origin: "past"`）だけは、正解が同じグループから複数選んでいる年があるため制約を外しています。
模範解答（`WINES.answers`）は `VOCAB` の項目ID・用語で書かれています。別シート（`sheets.js`）で採点するときは
`sheetAnswers()` が項目の統合（`from`）と用語の読み替え（`aliases`）を行い、シートに無い用語は採点対象外になります。

### データの出所

アプリ内では出所バッジで見分けられます。信頼度が違うので、混ぜて扱わないこと。

| バッジ | 対象 | 出所 |
|---|---|---|
| 📜 実物過去問 | `PAST_ANSWERS` の2015・2017・2018年（21本）、`PAST_EXAMS` の品種・生産国 | [ワイン受験.com](https://www.wine-jyuken.com/second_exam/kakonoseikai)（一般公開） |
| 📝 転記・未検証 | `PAST_ANSWERS` の2021〜2025年（31本）、`PAST_EXAMS` のヴィンテージ・出題番号・ソムリエ試験分、`WINES` の `origin: "past"`（27本） | [ニライカナイCH](https://niraikanao-ch1.com/tastingmatome-2026/) 2026年版シリーズ（個人ブログ） |
| 🧭 ブログ分析の定石 | `TEPPAN` | 同上。筆者が過去5年の模範解答から逆算した分析で、協会の公式見解ではない |
| 🍷 テイスティング会メモ | `WINES` の `origin: "note"`（6本） | 2026年9月12日（土）16:30〜18:00＠まるすけ（阿佐ヶ谷）のテイスティング会で、Wine-Flight 2025年版のシートに取った手書きメモ。開催情報は `NOTE_SESSION`。香りの語はメモどおり、メモにない項目は定石で補った。`memo` に元のメモ、`note` に補い方を記載 |
| 🤖 AI参考解答 | `WINES` の大半、`GRAPES`、`OTHERS` | AI作成 |

2019年以降の模範解答はJ.S.A.会員専用ページでのみ公開されるため、📝 は原本と照合できていません。
公式PDFを入手できたら差し替えてください。

なお、用語シートは市販・公開の解答用紙の様式に準拠し、模範解答の一部は個人ブログからの転記です。
著作権まわりの整理をしていないため、**不特定多数への配布は想定していません**。
同じ注意はアプリ内の3か所に表示しています。トップ画面に常時出る帯（押すと詳細が開く）、
トップメニューの ⓘ、📘使い方の「共有についてのお願い」です。

`WINES` の `origin: "past"` は実物の模範解答から作った練習ワインです。本試験の正解は選択数より多くの語を
正解と認めている項目がある（評価が2語、香辛料が10語など）ため、項目ごとの選択数は `VOCAB` の `pick` のままにし、
正解の語数がそれより少ない項目だけ正解の語数にします。採点もその選択数を分母にし、選択数ぶん当てれば満点です
（`app.js` の `pickFor` / `showResult`）。本番の指定が分かっているワインは `picks: { evaluation: 1, aromaSpice: 4 }` の
ように項目IDごとに書くと、その数が最優先で使われます（統合項目は元の項目の合計）。
生産地が既存ワインと重複するため、模範解答 比較閲覧の対象からは除いています。

## ご意見・不具合の報告の流れ

このアプリはサーバーを持たない静的サイトなので、報告の受け口は GitHub の Issue にしています。

1. **送る** — アプリのメニュー「📮 ご意見・不具合の報告」で、種類（不具合／機能の追加／その他）・件名・内容・該当画面を入力
2. **届く** — 「GitHubでIssueを作る」を押すと、内容を埋め込んだ新規Issue画面が開く。「Submit new issue」で登録される。
   GitHubを使わない場合は「内容をコピー」で同じ文面をクリップボードへ
3. **気づく** — 登録されるとリポジトリのWatch通知（メール／GitHubアプリ）が届く。一覧は
   [Issues](https://github.com/shin741216/wine-tasting-trainer/issues) で確認できる
4. **直す** — Claude Code に「新しい報告を見て」と頼むと、Issueを読んで実装しPRを出す。マージ後に `version.js` を上げると、
   アプリを開いたままのユーザーにも更新バーで届く

件名には種類の印（`[不具合]` `[機能追加]` `[その他]`）が付き、`bug` / `enhancement` のラベルが付きます。
GitHub側から直接立てる場合のために `.github/ISSUE_TEMPLATE/` にフォームも置いています。

自動で付く情報はアプリのバージョン・用語シート・画面サイズ・表示モード・ブラウザ・日時で、送信前に確認でき、
チェックを外せば付きません。個人を特定する情報は含めていません。
**Issueは公開される**ため、フォームにもその注意を表示しています。

## レイアウトの決まりごと

グリッドの伸縮する列は `minmax(0, 1fr)` で書きます。`1fr` のままだと中身（`white-space: nowrap` の
出所バッジなど）より狭くできず、列幅がばらついたうえ狭い画面で右にはみ出します。
実際に iPhone SE 幅（320px）でランチャーのタイルがずれて見切れていました。

## 比較表の見た目

横並びで見比べる表は4か所（実物正解 品種×年度、模範解答 比較閲覧、テイスティング会メモ、国・品種からコメントを探す）にあり、
文字サイズと列幅は `style.css` の「比較表の共通仕様」で一括して決めています。

| 変数 | 内容 |
|---|---|
| `--ct-col` | データ列の幅 |
| `--ct-item` | 左端の項目名列（固定表示）の幅 |
| `--ct-font` | 本文の文字サイズ |
| `--ct-head` | 見出しと項目名の文字サイズ |

画面幅で3段階（〜519px / 520px〜 / 768px〜）に切り替えます。列を狭くするほど横スクロールは減り、
そのぶんセル内で折り返して縦に伸びます。用語は `.ct-term` で囲み、語の途中ではなく語と語の間で改行します。

列幅は `<colgroup>` で指定します（`app.js` の `ctCols`）。`table-layout: fixed` は表の幅が `auto` だと
無効になり自動レイアウトへ戻ってしまうため、横スクロールする2つの表は列数から幅を計算して確定させています
（`app.js` の `ctWidth`）。テイスティング会メモの比較表だけは `width: 100%` で画面幅に収め、
用語を1語1行で並べます。

## 更新の配布

ファイルを変更して公開先へpushしたら、`version.js` の `APP_VERSION` を上げてください。
バージョンの管理場所はこの1か所だけです（`sw.js` は `importScripts` で同じ値を読み、
ページ側は更新の検知に使います）。

上げると、各端末では次のように反映されます。

- アプリを開き直した場合 — 起動時に新しいファイルを取得します
- **アプリを開いたままにしていた場合** — 復帰した時点（アプリスイッチャーから戻る、
  タブに切り替えるなど）でバージョンを確認し、更新があれば画面下に
  「新しいバージョンがあります」のバーを出します。「再読み込み」を押すと最新になります

再読み込みの前に、用語シートを記入中なら内容を自動で一時保存し、開いていた画面を控えます。
読み込み後は同じ画面・同じ記入状態で開き直し、「更新しました」のバーで結果を知らせます。
クイズと本番セット練習の途中だけは復元できないため、確認してから再読み込みします。
画面の記録は `localStorage` の `wtt-last-view` に置き、通常の復帰は30分、更新の再読み込みは
60分を過ぎたら使いません（`app.js` の `RESUME_MAX_AGE` / `UPDATE_RESTORE_MAX_AGE`）。
